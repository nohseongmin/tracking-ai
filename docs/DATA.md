# Data schema and observation contract

Source: [Esports Trajectories and Actions (ESTA)](https://github.com/pnxenopoulos/esta), Xenopoulos et al., [paper](https://arxiv.org/abs/2209.09861), CC BY-SA 4.0. Upstream format details and licensing are authoritative; the information here describes this project's processing.

## Storage

ESTA contains `data/lan/` and `data/online/`. Files are XZ-compressed JSON. Decompress individual files in memory using `lzma.open(path, 'rt', encoding='utf-8')`; there is no need to expand the entire dataset first.

```text
match JSON
  tickRate, playbackTicks, mapName
  parserParameters.parseRate
  gameRounds[]
    frames[]
      tick
      t.players[] / ct.players[]
        steamID, isAlive, x, y, z, isWalking, ...
```

Raw frames are time-ordered game snapshots. Player records become a time series when grouped by match, round, and `steamID`, then sorted by `tick`. The player identifier is used for grouping and never supplied to the model.

## Columns used

| Field | Role |
| --- | --- |
| `x`, `y`, `z` | Historical model inputs; future coordinates form the supervised target |
| `isWalking` | Historical model input; converted to 0 or 1 |
| `tick` | Sorting and continuity checks only |
| `steamID` | Player-track grouping only |
| `isAlive` | Eligibility filtering only |
| `tickRate`, `parserParameters.parseRate` | Seconds-to-ticks and future-horizon conversion |

Velocity, view direction, health, economy, weapons, opponent visibility, and the remaining player fields are excluded from the base model. Posture attributes are evaluated separately as an oracle diagnostic.

The attribute audit observed 44 distinct player fields. Their exact names are recorded in [player_columns.json](../results/pilot/player_columns.json).

## Prepared format

Each match producing samples is saved as an NPZ shard:

| Array | Shape | Meaning |
| --- | --- | --- |
| `x` | `(samples, 6, 4)` | Six relative XYZ positions and walking state |
| `y` | `(samples, 3)` | Relative XYZ at the target future time |
| `walking` | `(samples,)` | Last input walking flag for subgroup reporting |

The origin is the last observed XYZ. On disk, displacements remain in game units. Training divides XYZ inputs and targets by the training-only coordinate scale; walking flags are unchanged. Convert a model output back to an absolute coordinate using:

```text
predicted absolute XYZ = last observed XYZ + normalized output XYZ * training scale
```

`dataset_summary.json` maps each shard to a match-relative source filename, split, sample count, and timing metadata. A full preprocessing manifest is generated by the scripts; it is not distributed as raw data here.

## Limits of the current sound analogy

The benchmark assumes accurately localized historical positions as a stand-in for footsteps. It does not infer locations from waveforms or sound volume. `isWalking` is a recorded game flag, not an audio classifier. Silent intervals, localization noise, and false detections need an explicit observation policy before deployment.

Any input interval with near-zero movement is excluded by the current preprocessing rule. Consequently, reported scores do not establish performance on all hiding, stopping, or stealth behavior. Game maps, collision geometry, movement speeds, and sound observations will require separate validation in Unity.
